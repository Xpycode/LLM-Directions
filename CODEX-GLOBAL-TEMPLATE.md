# Global Codex Instructions

These instructions apply to Codex sessions using this Codex home. This file is deployed as
`$CODEX_HOME/AGENTS.md` (default: `~/.codex/AGENTS.md`).

## Directions

- **Local master:** `[LOCAL_DIRECTIONS_PATH]`
- A project uses Directions when `docs/PROJECT_STATE.md` exists (or `PROJECT_STATE.md` in the
  Directions master).
- Use the `directions` skill for `/setup`, `/status`, `/log`, `/decide`, `/learned`, `/spec`,
  `/make-plan`, `/execute`, `/check`, `/cookbook`, `/worktree`, `/test-app`, and `/directions`.
  Slashless forms such as `status arrive` and `log clear` are equivalent when a slash command is
  intercepted by the interface.
- The master `commands/*.md` files are the single procedural source of truth. Read the matching
  command completely before acting; do not copy or translate the command library into projects.
- Keep changing state in `docs/PROJECT_STATE.md`, `IMPLEMENTATION_PLAN.md`, specs, decisions, and
  session logs. Keep `AGENTS.md` limited to durable repository guidance.
- Universal Directions docs are read from the master on demand. Never restore copied `docs/00_*.md`
  or other universal mirrors in consumer projects.

## Project entry points

- `AGENTS.md` is the Codex entry point. `CLAUDE.md` is the Claude Code entry point.
- When both exist, keep stable project facts, commands, and safety constraints aligned, while
  leaving tool-specific behavior in its own entry point.
- Preserve existing instructions and user changes. Put a specialized override in the nearest
  nested `AGENTS.md` or `AGENTS.override.md` only when its narrower scope is intentional.

## Working defaults

- Inspect relevant files and current behavior before proposing or implementing a change.
- Preserve dirty-worktree changes and compare overlapping diffs before editing.
- Match validation to the files touched; do not claim a check passed unless it actually ran.
- In repositories affected by Syncthing or multi-Mac work, read
  `[LOCAL_DIRECTIONS_PATH]/37_multi-mac-discipline.md` before reconciling a missing `.git`, a dirty
  tree combined with remote changes, divergence, or a non-default branch that may already be merged.
- Prefer small direct commits or local branches when commits are requested; this is a solo-developer
  workflow, so do not introduce pull-request ceremony by default.
