# Global Vibe Instructions

These instructions apply to Mistral Vibe sessions using this Vibe home. This block is deployed
into `$VIBE_HOME/AGENTS.md` (default: `~/.vibe/AGENTS.md`).

## Directions

- **Local master:** `[LOCAL_DIRECTIONS_PATH]`
- A project uses Directions when `docs/PROJECT_STATE.md` exists (or `PROJECT_STATE.md` in the
  Directions master).
- Use the `directions` skill for `/setup`, `/status`, `/log`, `/decide`, `/learned`, `/spec`,
  `/make-plan`, `/execute`, `/check`, `/cookbook`, `/worktree`, `/test-app`, and `/directions`.
  In Vibe, slashless forms such as `status arrive` and `log clear` are primary: built-in commands
  intercept `/status` and `/log` before the model sees them.
- The master `commands/*.md` files are the single procedural source of truth. Read the matching
  command completely before acting; do not copy or translate the command library into projects.
- In Directions projects, requests to execute/resume an approved plan (including “continue
  implementation” or “next wave”) route through the `directions` skill and `commands/execute.md`.
  Follow its dependency, fresh-context delegation and validation rules; continue ready work within
  the user's authorized scope without renewed task/wave permission. Explicit user limits prevail.
- Keep changing state in `docs/PROJECT_STATE.md`, `IMPLEMENTATION_PLAN.md`, specs, decisions, and
  session logs. Keep `AGENTS.md` limited to durable repository guidance.
- Universal Directions docs are read from the master on demand. Never restore copied `docs/00_*.md`
  or other universal mirrors in consumer projects.

## Vibe specifics

- `AGENTS.md` is the Vibe project entry point (Vibe reads it natively); `CLAUDE.md` is the Claude
  Code entry point. Keep stable project facts aligned between them, but keep tool-specific
  behavior separate.
- Vibe has no session-start hook. When the master's `hooks/session-start.sh` exists and shell use
  is allowed, run it once at session start for the concurrency check; otherwise rely on repository
  evidence. Treat hook output as optional convenience, not workflow state.
- Vibe subagents start with a fresh session: supply the task packet explicitly instead of relying
  on a conversation fork. Delegate only when the user or active instructions allow delegation.
- The user's no-desktop-control preference applies in every Vibe session.

## Working defaults

- **Shortcut readability:** in chat, questions, documentation and app-authored UI copy, spell out
  modifier and special-key names (for example, Command-Shift-P or Command-Comma); do not use
  shortcut glyphs, even with spaces. Native macOS menus retain their system-rendered symbols.
- **Fresh-build handoff authorization (October 27, 2026):** after successfully producing a fresh
  runnable app build for user testing, launch the exact fresh artifact without asking again.
  If replacement is needed, gracefully quit only the identified instance of the target app,
  confirm it exited, then launch and verify the running executable path and version against the
  fresh artifact. Stop if the app is busy, refuses to quit, or presents an unsaved-work prompt;
  never force quit or dismiss the prompt. This supersedes the October 18 launch-only restriction
  for this handoff. Failed builds, intermediate test-runner builds, app-hosted tests, clicks,
  keystrokes, window/Space manipulation, clipboard changes and live app-profile replacement are
  outside this permission. Report the full artifact path and verified quit/launch result. Newer
  no-control or keep-running instructions prevail. Procedure: `reference/log/app-handoff.md`.
- Inspect relevant files and current behavior before proposing or implementing a change.
- Preserve dirty-worktree changes and compare overlapping diffs before editing.
- Match validation to the files touched; do not claim a check passed unless it actually ran.
- In repositories affected by Syncthing or multi-Mac work, read
  `[LOCAL_DIRECTIONS_PATH]/37_multi-mac-discipline.md` before reconciling a missing `.git`, a dirty
  tree combined with remote changes, divergence, or a non-default branch that may already be merged.
- Prefer small direct commits or local branches when commits are requested; this is a solo-developer
  workflow, so do not introduce pull-request ceremony by default.
